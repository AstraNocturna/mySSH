# mySSH AI 接入（MCP）说明

[English](ai-mcp.en.md) | 简体中文

mySSH 内置一个 MCP 服务端。Claude Code、Cursor、OpenCode、Droid 等 AI 编程助手接入后，可以直接在你保存的会话上执行命令、读写文件、传输文件、操作交互式终端。

AI 能做什么、要不要先问你，全部由你决定。凭据始终留在本机，AI 只能看到会话名称和主机信息，看不到密码和私钥。

## 开启与接入

1. 打开「设置 → MCP」，勾选「启用 MCP 服务端」（默认关闭）。
2. 点「一键复制配置」，选择你用的客户端（omp、Claude Code、OpenCode 或通用格式）。
3. 把配置粘贴到客户端的 MCP 配置文件里，重启客户端。

服务端只监听本机 `127.0.0.1`（默认端口 17345），使用 Bearer 令牌鉴权。令牌可以在设置里复制或重新生成。

通用配置格式如下（Claude Code、Cursor、Droid 等都认这个格式）：

```json
{
  "mcpServers": {
    "myssh": {
      "type": "http",
      "url": "http://127.0.0.1:17345/mcp",
      "headers": { "Authorization": "Bearer <令牌>" }
    }
  }
}
```

## 工具一览

共 31 个工具，按用途分组：

| 分组 | 工具 | 用途 |
| --- | --- | --- |
| 会话 | `list_sessions` | 列出会话档案（不含凭据），以及每个会话对 AI 的授权情况、已打开的标签、AI 可直接使用的终端 |
| 执行命令 | `ssh_exec` | 执行一条命令，返回输出和退出码。输出会去掉颜色控制符，超长时保留头尾，省 token |
| 运维模板 | `recipe_list` / `recipe_run` | 16 个内置运维模板：系统概况、磁盘占用、进程排行、端口、服务状态与日志、Docker 容器、重启服务等。每个模板标有风险等级，参数先校验再代入 |
| 后台命令 | `job_start` / `job_read` / `job_stop` / `job_list` | 构建、`tail -f`、大文件下载等长时间命令放到后台跑，随时分段读取输出或停止 |
| 交互终端 | `terminal_open` / `terminal_send` / `terminal_read` / `terminal_list` / `terminal_close` | 打开有状态的 shell，用于 REPL、分页器等 `ssh_exec` 驱动不了的场景。`terminal_read` 可以等到出现提示符或输出静止再返回 |
| 文件浏览 | `sftp_home` / `sftp_list` / `sftp_stat` / `sftp_read` | 浏览远端目录、读文件 |
| 文件修改 | `sftp_write` / `sftp_mkdir` / `sftp_delete` / `sftp_rename` / `sftp_chmod` | 写文件、建目录、删除、改名、改权限 |
| 文件传输 | `sftp_upload` / `sftp_download` / `sftp_transfer_list` | 走后台传输队列（和界面里的传输面板共用），没有大小限制 |
| 文件编辑 | `file_view` / `file_edit` / `file_grep` / `file_glob` | 带行号分页查看、精确替换编辑（防止覆盖别人同时做的修改）、正则搜索、按通配符找文件。全部经 SFTP 完成，不在远端执行命令 |
| 备份回滚 | `file_backups` / `file_rollback` | AI 改文件前自动备份原内容，可以一键回滚 |

## 权限：AI 能用哪些工具

工具分成 6 个权限组：会话列表、执行命令（含后台命令和运维模板）、SFTP 读取、SFTP 写入、SFTP 传输、交互终端。

每个会话的权限按「会话 → 所在分组 → 全局」的顺序确定，越具体的设置优先：

- **全局默认**：「设置 → MCP」里设置 6 个权限组的开关和访问档位。
- **分组策略**：在侧边栏分组上右键 →「MCP 策略」。子分组和分组里的会话会继承。
- **会话覆盖**：会话编辑器的「MCP 权限」页签，每一项都可以继承或单独设置。

常见用法：测试机全部放开，生产机只允许查看。

「交互终端」默认关闭，因为在终端里敲的按键无法经过命令策略检查，开启前请确认你信任这个 AI。

## 命令策略：哪些命令要先问你

AI 通过 `ssh_exec`、后台命令和运维模板执行的每条命令，都会先经过命令策略分析。分析结果决定直接执行还是先弹框问你。

**访问档位**（默认「只读」）：

| 档位 | 直接执行 | 需要你确认 | 直接拒绝 |
| --- | --- | --- | --- |
| 只读 | 能证明是只读的命令（白名单命令且参数不写系统） | 下面列出的强制确认命令 | 其余命令 |
| 标准 | 能证明是只读的命令 | 其余命令 | 无 |
| 完全 | 下面列出的强制确认命令以外的命令 | 强制确认的命令 | 无 |

以下命令在任何档位都必须你确认（强制确认）：

- 黑名单命令，如 `rm`、`dd`、`mkfs`；
- 间接执行器，即会再去执行别的命令或脚本的程序，如 `bash`、`xargs`、`sudo`；
- 无法静态分析的写法，如子 shell、不配对的引号；
- 标为「生产环境」的会话上所有不能证明只读的命令。

`sudo rm` 这类带前缀的命令会检查前缀后面真正执行的命令，不能借前缀绕过黑名单。

三份名单（白名单、黑名单、间接执行器）可以在「设置 → 命令策略」里增删，各自可以恢复默认。改完后下一条命令立即生效，不用重启。

## 授权框

需要确认的命令会在 mySSH 里弹出授权框：

- **标明是哪台机器**：显示会话名称、用户和主机、所在分组，生产环境有红色标记。可以一键跳到这个会话的终端。
- **说明命令在做什么**：用一句话概括整条命令，列出需要确认的原因（例如「可能修改系统：git pull、npm、pm2」）。AI 填写的用途也会显示出来，并标注「未经验证」。
- **默认是拒绝**：焦点在「拒绝」按钮上，按钮显示剩余秒数，5 分钟没有处理会自动拒绝。
- **自动执行**：勾选「自动执行（本会话后续命令）」后，这个 AI 在这个会话上后面需要确认的命令仍会弹框，但会自动勾选并在 3 秒后执行，你可以随时取消。黑名单命令不能自动执行。AI 客户端断开后自动失效。
- **多个会话同时请求**：左侧按会话分组列出，可以「拒绝本会话全部」，批准必须逐条进行。
- 窗口在后台时任务栏会闪烁提醒。没有可用窗口时一律拒绝。

每个会话默认每分钟最多 60 次调用（设置键 `mcp.rate_limit_per_minute`）。

## 看得见 AI 在做什么

- **命令镜像**：AI 用 `ssh_exec` 执行的命令、实时输出和退出码，会显示在对应会话终端下方的只读分屏里，不影响你正在用的终端。可以在「设置 → MCP」关闭。
- **AI 终端就是普通标签**：AI 打开的交互终端以普通标签显示，你可以旁观；你一打字 AI 就暂停写入；右键可以随时收回控制。你也可以把自己的标签「共享给 AI」。
- **AI 活动面板**：点工具栏的「AI」按钮，按会话列出待确认的命令、正在执行的命令、后台命令和 AI 终端，每一项都能一键停止。标签栏和侧边栏也会显示「AI 执行中」「待确认」徽标。

## AI 断开后自动收尾

每个 AI 客户端连接时会领取自己的会话号，断开时只清理它自己留下的东西：

- 拒绝并关闭它的待确认授权框；
- 停止它正在执行的命令和后台命令；
- 关闭它的 AI 终端（标签保留，只收回 AI 控制）和只有它用过的命令镜像；
- 底部弹出提示，列出清理了哪些内容。

判断断开的方式：长连接断开 30 秒没有重连，或客户端主动结束会话。不保持长连接的客户端无法确认是否已经关闭，30 分钟没有请求时会弹框问你「退出 AI 托管」还是「保留」。

## 留痕：审计、录像与回滚

- **审计日志**：AI 的每次调用和你的每次决定都会写入审计日志。日志用哈希链串起来，事后被改动可以校验出来。
- **终端录像**：AI 控制的终端全程自动录像，包括 AI 输入的内容。录像结束时把文件的 SHA-256 记入审计日志。在命令面板打开「会话录像」可以回放并校验录像是否被改过。
- **文件回滚**：`file_edit`、`sftp_write`、`sftp_delete` 改动前会自动备份原文件。在侧边栏会话上右键 →「AI 文件改动…」可以查看每次改动的标题和摘要，一键回滚。如果文件在 AI 改动之后又被别人改过，默认拒绝回滚，避免覆盖别人的修改。
- **保留期限**：备份默认保留 7 天，审计日志保留 30 天，可以在「设置 → 通用 → 历史记录保留」调整。
